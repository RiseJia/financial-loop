# 调研循环：退出准则的设计与自动化

> 工具：`finloop loop-status`（退出码 0=可退出 / 1=有任务）
> 状态文件：`config/research_state.yaml`

## 问题：一轮调研什么时候算"完成"？

两个直觉答案都是错的：

- **"跑过一轮就算完成"** ❌ —— 信息会过期。CoWoS 预订深度、提价落地、
  交期数据都有保质期，三个月前的"售罄"今天可能已经缓解；
- **"测试某个市场指标"** ❌ —— 指标（股价/估值）验证的是**论点对不对**，
  不是**调研全不全**。两者必须分开：论点可以错但调研完备，也可以论点
  暂时对但调研已经过期。

正确答案：**调研永远不会完成，只能满足"本轮退出条件"**。退出 ≠ 结束，
而是把完备且新鲜的状态**交接给监控**，等待三类事件触发下一轮。

## 退出条件：三层判定（前两层全自动）

| 层 | 判定内容 | 自动化 | 实现 |
|---|---|---|---|
| ① 完备性 | 每个节点有证据条目 + 证伪触发器（结构 lint） | ✅ 全自动 | `incomplete` 检查 |
| ② 新鲜度 | 证据时间戳与触发器核对时间在保鲜期内（默认 90 天 = 一个财报季） | ✅ 全自动 | `stale_*` 检查 |
| ③ 未决问题 | open 状态的问题清零（回答掉，或显式 deferred 并注明理由） | 半自动（清单自动，回答靠人） | `open_questions` 检查 |

**三层全绿 → 退出码 0 → 本轮可退出。任何一层不绿，`loop-status` 的
输出就是下一轮任务清单**——不需要人来决定"接下来调研什么"。

关键设计决策：**论点信号（triggers 的 warning/fired）不阻塞调研退出**。
触发器亮黄灯说明论点可能有问题，那是投资判断层的事（人工裁决 + 仓位
动作）；调研退出管的只是"信息是否完备新鲜"。把这两件事混在一起，
会导致"论点有争议→调研永远关不掉"的死循环。

## 下一轮的触发：三类事件

```
                ┌──────────────────────────────────┐
   ┌──────────▶│ 调研轮（挖掘+核验+更新 state.yaml）│
   │            └──────────────┬───────────────────┘
   │                  loop-status 全绿（退出码0）
   │                           ▼
   │            ┌──────────────────────────────────┐
   │            │ 监控态（日报 + 触发器面板挂机）     │
   │            └──────────────┬───────────────────┘
   └───────────────────────────┘
     重新入轮的三类事件：
     ① 日历触发：保鲜期到期（财报季，90天）→ stale 清单自动生成
     ② 信号触发：某触发器变 warning/fired → 该节点定向重审
     ③ 发现触发：新节点/新公司进入视野 → frontier 转正式节点
```

## 饱和度：什么时候停止"继续深挖"

广度方向的退出（"这个角落还要不要挖"）用**边际发现率**判断：
每轮在 `meta.rounds` 记录 `new_nodes / new_tickers`。当一个子链连续
一轮新增为零（搜索结果全部指向已收录的玩家与信源），该子链转入
**维护模式**（只做新鲜度更新），探索资源转向 `frontier` 列表的下一项。

frontier 是显式维护的"已知的未知"清单——它的存在本身就回答了
"还有什么没挖"：挖完一项划掉一项，发现新角落就追加。

## 状态文件的纪律

1. **每条证据必须带 `asof` 日期**——没有日期的证据无法判定新鲜度，
   等于没有证据；
2. **每个节点必须有触发器**——没有证伪条件的论点不是研究是信仰
   （结构 lint 会拦截）；
3. **问题只有三种状态**：open（阻塞）/ deferred（显式搁置+理由）/
   直接删除（已回答，答案进研究报告）。不允许"悬着"；
4. 调研轮结束时更新 `meta.rounds`，记录本轮范围与发现计数——
   这是饱和度判断的原始数据。

## 与其他部件的咬合（参照 docs/workflow.md）

- `loop-status` 的退出码可挂进 CI/cron：财报季自动跑，不绿则开 issue/提醒；
- 触发器的 `status` 字段由人（或日报扫描）更新，`last_checked` 是
  "我看过了"的签到——把"应该盯的事"变成"盯过没有的记录"；
- 深挖问题的答案沉淀进 `reports/research/`，问题从 yaml 中删除——
  **yaml 是状态，报告是历史**。
