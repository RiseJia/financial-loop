# AI 产业链研究方法论：在上游寻找「需求 >> 估值」

> 工具入口：`finloop screen --tier upstream`（漏斗第一层）
> universe 维护：`config/universe_ai.yaml`

## 一、产业链地图与资金流向

```
下游应用(变现) → 中游平台(云/算力运营) → 上游供给(芯片/设备/电力/物理层)
   PLTR/NOW...      MSFT/GOOGL/AMZN/        NVDA→TSM→ASML/AMAT
                    META/ORCL/CRWV          AVGO/MU/ANET/VRT/CEG...
```

核心传导链：**下游的收入预期 → 中游的资本开支 → 上游的订单**。
所以研究上游需求，最硬的领先指标不在上游自己嘴里，而在中游的财报里：

- **超大规模云厂 capex 指引**（MSFT/GOOGL/AMZN/META 每季财报电话会）
  是全部上游需求的总闸门。四家合计 capex 的同比变化 ≈ 上游行业景气度一阶导。
- 中游 capex 上修 → 顺着物料清单（BOM）找受益弹性最大的环节。

## 二、「需求 >> 估值」的可操作定义

口号量化成可检验的命题：**基本面增长的市场定价不足**。三层证据，硬度递增：

| 层级 | 证据 | 数据来源 | 硬度 |
|------|------|---------|------|
| 1 | 营收/盈利增速 vs forward PE、PEG 的横截面错位 | 免费（screener 自动） | 初筛 |
| 2 | 毛利率扩张（涨价能力=供需紧张的财务表现）、经营杠杆释放（盈利增速>>营收增速） | 免费（screener 自动） | 中 |
| 3 | backlog/RPO 增长、交期(lead time)拉长、产能利用率、下游 capex 指引上修 | 财报原文/电话会（人工） | 硬 |

screener 只覆盖 1-2 层，它的工作是把 30+ 个上游标的排序成「值得花
人工读财报的前 5 名」。第 3 层没有捷径——读季报的 RPO/backlog 披露、
听电话会里的交期表述（"lead times extended" 是上游最甜的词）。

## 三、上游的特殊风险（估值便宜的常见原因）

需求强 + 估值低的组合，先排查这四个"便宜的理由"：

1. **周期性**：设备/存储是强周期行业，低 PE 常出现在周期顶（市场定价
   的是下行）。看：库存周转变化、订单出货比（B/B ratio）。
2. **客户集中度**：上游公司常有单一客户 >30%（如某 GPU 大客户），
   需求被砍单时弹性极大。10-K 的客户集中度披露必读。
3. **二供风险**：定制 ASIC 对 GPU 的替代、客户自研，技术路线切换会让
   "需求"瞬间转移。问：这家公司的需求绑定的是 AI 总量，还是某条技术路线？
4. **产能释放**：紧缺驱动的毛利率扩张会被新产能磨平（存储行业的永恒剧本）。

## 四、与框架其他模块的配合

```
finloop screen --tier upstream     # ① 横截面初筛 → 深挖名单
finloop analyze VRT                # ② 单票全景：趋势/动量/基本面清单
finloop signals MU --days 60       # ③ 拐点与动量切换（介入时机参考）
finloop research --tier upstream   # ④ 策略在这批票上的横截面回测
（人工）读财报第3层证据            # ⑤ 最终决策的核心，工具替代不了
```

纪律：screener 的 gap 排名**每季度财报后重跑**——上游的需求-估值错位
是动态的，上季的便宜货可能已被市场修复（或基本面恶化证明了市场是对的）。
