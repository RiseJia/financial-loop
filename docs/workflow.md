# 工作流总纲：整个体系如何咬合

> 这是整个 repo 的"地图的地图"。回答一个问题：调研、筛选、策略、验证、
> 数据这些部分各管什么、按什么顺序咬合、循环怎么转。

## 一、五个部件的正确分工

```
                ┌─────────────────────────────────────────────┐
                │              ⓪ 数据层（地基，横切）           │
                │   多源行情+质量门+基本面防线+快照存档          │
                │   ——它不是流程的一步，它是所有步骤的脚下之地    │
                └─────────────────────────────────────────────┘
                       ▲ 支撑所有层（坏数据 = 所有结论静默作废）
┌──────────┐    ┌──────────────┐    ┌──────────────────┐
│ ① 调研    │───▶│ ② 分析筛选     │───▶│ ③ 策略/信号        │
│ 产业理解   │    │ 买什么·值不值  │    │ 何时进·拿多少·何时出 │
│ 标的发掘   │    │   (WHAT)      │    │  (WHEN / HOW MUCH) │
│ 论点+证伪器 │    └──────────────┘    └──────────────────┘
└──────────┘            │                      │
      ▲                 ▼                      ▼
      │           ┌─────────────────────────────────┐
      └───────────│ ④ 验证（横切职能，不是一个阶段）     │
   季度循环回流     │  数据→质量门  筛选→人工核验+对照     │
                  │  策略→回测/事件研究  论点→证伪面板    │
                  └─────────────────────────────────┘
```

### ① 调研：不只是"发掘标的"

产出**三**样东西，后两样常被忽略：
1. **标的池**（universe）——发掘环节，到原材料加工厂粒度；
2. **需求侧论点**——每个子链"为什么会赚钱"的因果链（提价/交期/backlog 证据）；
3. **证伪触发器**——论点在什么数据出现时宣告死亡。

第 3 项让调研从"一次性任务"变成**循环**：每季财报后重新核对触发器
→ 论点续期或淘汰 → 更新标的池。这就是 repo 名字里的 loop。

对应物：`docs/chain/`（理解）、`docs/ai_supply_chain_map.md`（地图）、
`reports/research/*deep_dive.md`（论点+触发器）、`config/universe_ai.yaml`（池）。

### ② 分析筛选：回答"买什么、什么价格值得"——不是选时点

⚠️ 常见混淆：「选择好的 entry」有两个含义——**选标的**（selection）和
**选时点**（timing）。筛选只管前者。它输出的是：
深挖名单 + 每个标的的"值得买的价格区间/条件"（如：Nittobo 若一次性收益
拆干净后真实 PE <20x 且 4 月提价落地，则…）。

对应物：`finloop screen`（量化横截面）+ 人工核验（估值验证报告的流程）
+ `finloop analyze`（单票全景）。

### ③ 策略/信号：买入前就开始工作，不是"买入后"

⚠️ 第二个常见混淆：策略不是持仓后才启用。它管三件事，第一件发生在买入前：
1. **何时进**（timing）：筛选给了"值得买的名单"，但好公司也会跌 30%——
   regime 状态机 + 拐点/动量信号决定具体的进场时机（例：名单标的出现
   "RSI 超卖回升 + 收复 200 日线"才分批进）；
2. **拿多少**（sizing）：ATR 仓位法、单标的上限、周期面板决定总水位；
3. **何时出**（exit）：止损纪律（2×ATR/跌破 200 日线）、证伪触发器命中、
   基本面逻辑破坏（长线卖出三理由）。

对应物：`finloop signals/intraday`、`signals/regime.py`、
`docs/long_term.md` 与 `docs/intraday.md` 的纪律部分。

### ④ 验证：横切职能，每层有自己的验证方式

| 被验证对象 | 验证手段 | 已发生的实例 |
|---|---|---|
| 数据 | 质量门+双源对账+基本面一致性防线 | Nittobo fPE 错 3 倍被人工抓出→自动化成防线 |
| 筛选 | 人工核验关键数字 + 定性×量化交叉对照 | 估值验证报告（MU 周期顶口径被拆穿） |
| 策略 | 回测+事件研究+情景压测（历史统计） | sma200=回撤保险的双重验证 |
| 论点 | 证伪触发器面板（只能被未来验证） | "SK 砍单"黄色信号已亮 |
| 代码本身 | 测试套件+红队审计 | 2 MAJOR 10 项修复 |

### ⓪ 数据：你说得完全对，再加一句

数据对分析/策略/验证都关键——正确。要加的一句是：**数据问题的危险形态
是静默的**（错数据长得和对的一样），所以数据层的投入不是"基础设施成本"，
是直接的研究质量保险。Nittobo 事件 = 一个错数字差点筛掉定性第一的标的。

## 二、缺的第五块：风险管理

你的四分法少了一块，它不属于任何一步而约束所有步骤：
- 仓位水位 ← 周期面板（`docs/chain/08`，≥3 信号转向则降档）；
- 单笔风险 ← ATR 仓位法（`docs/indicators.md` ATR 节）；
- 集中度 ← 单标的 ≤15-20%、单子链上限（`docs/long_term.md`）；
- 操作纪律 ← 不用战术信号回答战略问题（08 篇结尾）。

## 三、一个标的的完整生命周期（把所有部件串起来）

```
调研发现(Nittobo, T-glass 90%垄断)            ① finloop 外：agent 调研
→ 进 universe + 写论点与证伪器                 ①
→ screen 打分 + 人工核验(修正错数据)           ② + ④
→ 进深挖名单, 写"值得买的条件"                 ②
→ 等待: signals 盯拐点, 周期面板定水位          ③ + 风险管理
→ 条件满足 → 按 ATR 定仓分批进                 ③
→ 持有: 季度核对证伪器, 日报盯信号              ①循环 + ③
→ 退出: 触发器命中/逻辑破坏/趋势纪律            ③ + ①
→ 复盘进 reports/, 教训回流框架                ④（如基本面防线的诞生）
```
